# Решение: Gemini CLI становится дефолтным воркером, Sonnet/Haiku уходят в резерв

## Контекст

Текущая архитектура (v1, от 28.04.26): Opus = оркестратор, Sonnet = writer/coder/researcher/analyst, Haiku = fileops/inbox/relay. Расчётная стоимость ~$1.5–2/день. Для текущей фазы (наполнение vault'а, ТЗ, исследования, рутина) это всё ещё больше, чем хочется.

Появилась рабочая возможность: Gemini CLI на бесплатном тарифе личного Google-аккаунта. Лимиты ~60 запросов/мин и ~1000/день, доступ к Gemini 2.5 Pro/Flash, контекст до ~1M токенов, встроенный Google Search.

## Решение

С 08.05.26 переходим на v2:

1. **Gemini CLI = дефолтный воркер** для writer / coder ≤ 200 строк / researcher / analyst / inbox-парсинга / форматирования / fileops через bash.
2. **Sonnet остаётся резервом** для high-stakes: юр./налоги/деньги, customer-facing копирайт, сложный код, задачи с чувствительными данными (ИНН, тендерные доки, клиентские реквизиты).
3. **Haiku остаётся** только в одной точке — telegram-relay `/ask` (там уже плумбинг). Новых случаев Haiku не плодим.
4. **Opus** — без изменений, остаётся оркестратором.

Полные правила маршрутизации, Mermaid и экономика — в [[Multi_Agent_Architecture]] v2. Операционка (как звать, где логи, как промпты) — в [[Gemini_CLI_Setup]].

## Почему именно сейчас

- Стоимость Sonnet/Haiku, хотя и небольшая в абсолюте, неоправданна для рутинных задач, которые тянет бесплатный воркер.
- 1M контекста Gemini закрывает класс задач, который Sonnet/Haiku тянули с трудом (длинные документы, большие выгрузки).
- Встроенный Google Search экономит шаги «Sonnet ищет → возвращает → Opus просит ещё».
- Текущая фаза бизнеса — много рутинной writing/research-работы, мало high-stakes действий, где Sonnet реально нужен. Соотношение играет в пользу Gemini.

## Что взвешено и принято

**Приватность.** Бесплатный тариф Gemini по ToS Google может использовать промпты для улучшения модели. Поэтому в Gemini сознательно НЕ отправляем: ИНН/ОГРН контрагентов в связке с коммерцией, тендерные документы клиентов, финансовые показатели по конкретным сделкам, реквизиты конкретных людей. Эти задачи идут в Sonnet (платный API → не для обучения по политике Anthropic).

**Лимиты.** ~1000 запросов/день. Для текущего объёма с запасом, но при включении одновременно ежедневного inbox-digest + парсера + research — край близко. Если упрёмся, страховка — Haiku.

**Качество кода.** На простом Gemini не хуже Sonnet, на сложном рефакторинге Sonnet надёжнее. Дефолт: Gemini пишет → Opus читает diff → если запах, отдаём Sonnet'у.

**Операционка.** Gemini внешний, требует bash-плумбинга / MCP. Не такой бесшовный, как нативные subagent'ы Anthropic. Принимаем как разумную плату за ноль стоимости.

## Триггеры отката (когда возвращаемся к Sonnet как дефолту)

- Доля «Gemini справился с первого раза» < 70% по логам в `99_System/logs/` за неделю — сначала корректируем промпты, если не помогает — откат.
- Регулярное упирание в дневной лимит, блокирующее работу.
- Объём чувствительных задач вырос так, что Sonnet всё равно зовётся в большинстве случаев — переключения туда-сюда дороже монолита.
- Anthropic выкатит сопоставимое по бесплатности (бесплатный кредит, корпоративный тариф) — переключаемся обратно.

## Метрика для контроля

Считаем по логам в `99_System/logs/` раз в неделю:

- Всего вызовов Gemini.
- % `verdict: ok` (с первого раза).
- Сколько раз `escalated_to: sonnet`, что это были за задачи.
- Затраты Sonnet/Haiku в Anthropic-кабинете.

Цель: > 70% Gemini-ok, расходы Anthropic < $1/день в спокойную неделю.

## Что меняется в моих ежедневных правилах (для Opus)

Перед любой делегируемой задачей сначала спрашиваю:

1. Это меньше 2 минут работы? → делаю сам.
2. Чувствительные данные? → Sonnet.
3. High-stakes (юр./деньги/customer)? → Sonnet.
4. Сложный код / рефакторинг? → Sonnet.
5. Иначе → **Gemini по умолчанию**.

После Gemini — обязательная проверка diff'а перед записью артефакта. Лог в `99_System/logs/` с заполненным `verdict`. Резюме в `Delegation_Log.md`.
