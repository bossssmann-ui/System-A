# Carrier Lookup Service — автопроверка контрагента по ИНН

> **Статус**: Идея/черновик ТЗ. Реализация после MVP парсера тендеров.
> Открыто: 28.04.26 по запросу Романа.
>
> **Цель**: убрать у диспетчера ручную работу по сбору документов и проверке контрагентов в открытых базах. Один ввод ИНН → готовая карточка с риск-скорингом.

## Постановка задачи

### Проблема (сейчас)

Диспетчер при появлении нового контрагента (Модель B) вручную:
1. Звонит логисту в Москве, просит документы.
2. Открывает 7+ сайтов (egrul, pb, fssp, kad.arbitr, fedresurs, zakupki РНП, **ГосЛог**) и проверяет каждый по ИНН.
3. Складывает результаты в карточку УЛ.
4. Выставляет рекомендацию.

Это **30–60 минут на одного контрагента**. При потоке 20 новых контрагентов в месяц — потеря 10–20 часов диспетчерского времени.

### Решение (вижн)

```
[Диспетчер]
   ↓ вводит ИНН
[Carrier Lookup Service]
   ├─ Параллельно:
   │   ├─ Запрос документов у логиста (email + форма загрузки)
   │   └─ Парс открытых баз по ИНН
   │       ├─ ЕГРЮЛ (egrul.nalog.ru — открытое API)
   │       ├─ ФНС "Прозрачный бизнес" (pb.nalog.ru — парсинг)
   │       ├─ ФССП (открытый API)
   │       ├─ kad.arbitr.ru (парсинг)
   │       ├─ bankrot.fedresurs.ru (парсинг)
   │       ├─ РНП на zakupki.gov.ru (парсинг)
   │       └─ Реестр ГосЛог (ручная или через интеграцию когда появится API)
   ↓
[Pre-filled карточка контрагента]
   ├─ Все поля заполнены
   ├─ Подсветка красных флагов
   ├─ Риск-скоринг (Высокий / Средний / Низкий)
   └─ Кнопка "Передать бухгалтеру на финальную проверку"
```

## Функциональные требования

### F.1 Ввод
- ИНН (обязательно).
- Тип контрагента: АТП / Экспедитор / Не уверен (диспетчер выбирает).
- Логист, который привёл контрагента (выбор из списка для отправки запроса документов).

### F.2 Запрос документов у логиста
- Автогенерируется email на адрес логиста.
- В письме — список требуемых документов (зависит от типа контрагента).
- В письме — уникальная ссылка на форму загрузки сканов.
- При загрузке через форму документы автоматически попадают в карточку контрагента в УЛ.
- Напоминание логисту через 24 часа, если не загрузил.

### F.3 Открытые базы
- ЕГРЮЛ, ФНС, ФССП, kad.arbitr, fedresurs, РНП — параллельные запросы.
- Время выполнения: ≤30 секунд (асинхронно с возможностью посмотреть промежуточный результат).

### F.4 Сводка
- Все поля карточки заполнены (см. ЧАСТЬ C в `Carrier_Audit_Checklist.md`).
- Красные флаги — отдельным блоком сверху.
- Риск-скор — высокий/средний/низкий с обоснованием.

### F.5 Передача бухгалтеру
- Кнопка "Запросить финальное заключение бухгалтера".
- В карточке статус меняется на "На финальной проверке".
- Бухгалтер получает уведомление в её рабочем интерфейсе.

## Нефункциональные требования

- Развернуть на том же VPS, что и парсер тендеров (общий сервер, экономия).
- Доступ — через УЛ или отдельную страницу (решим на этапе UI).
- Логи всех проверок хранятся 3 года (для налоговой защиты).

## Источники данных — детально

| Источник | Доступ | Сложность | Примечания |
|---|---|---|---|
| ЕГРЮЛ | Открытое API egrul.nalog.ru | Низкая | JSON-ответ, легко парсится |
| ФНС "Прозрачный бизнес" | pb.nalog.ru, парсинг | Средняя | API закрыт, нужен парсер страниц |

| СПАРК / Контур.Фокус | Платное API | Низкая | 50–200K ₽/год, можно подключить позже |

## Технологический стек (предварительный)

- **Backend**: Python 3.10+, FastAPI / Flask.
- **Парсеры**: Playwright (для kad.arbitr и других с антиботом), requests (для API).
- **БД**: PostgreSQL или SQLite (для MVP).
- **Очередь**: Celery / RQ (для параллельных запросов).
- **Email-шаблоны**: Jinja2 + SMTP компании.
- **UI**: либо встроить в УЛ через API, либо отдельная мини-страница на FastAPI + HTMX.

## Этапы разработки

### Этап 1. MVP — только открытые базы (1 неделя)
- Ввод ИНН → ЕГРЮЛ + ФНС + ФССП + bankrot.
- Простая таблица результатов.
- Без формы для логиста.

### Этап 2. Полная цепочка (1 неделя)
- Подключить kad.arbitr, РНП.
- Сборка карточки контрагента в формате полей УЛ.
- Риск-скоринг.

### Этап 3. Запрос документов у логиста (1 неделя)
- Email-шаблоны.
- Форма загрузки.
- Связка с УЛ (через API УЛ или экспорт в УЛ).

### Этап 4. ГосЛог-интеграция (когда появится)
- Подписаться на новости ГосЛог об открытии API.
- При появлении — добавить как ещё один источник.

| Источник | Реальный путь доступа | Комментарий |
|---|---|---|

Для MVP реалистично: либо парсинг сайта с CAPTCHA-сервисом, либо сторонний агрегатор |
| **ФНС «Прозрачный бизнес»** (pb.nalog.ru) | Только парсинг веб-интерфейса | Публичного API нет. Антибот, CAPTCHA, регулярные изменения HTML |
| **ФССП БДИП** (fssp.gov.ru) | **Есть официальное API**: `api-ip.fssp.gov.ru/`. Регистрация на `api-ip.fssp.gov.ru/register`, ключ передаётся в каждом запросе. Открытые данные: `opendata.fssp.gov.ru/` | Это самый чистый из всех источников. С 05.2025 запущен ещё реестр алиментных должников |

Платные сторонние API: `parser-api.com`, `damia.ru/apiarb`, `api-cloud.ru/kad_arbitr`, `you-right.ru`, `newdb.net` — все берут данные парсингом и продают как сервис | Для MVP реалистично: сторонний API. Самим парсить — отдельный проект |
| **bankrot.fedresurs.ru / ЕФРСБ** | **Есть официальный REST API**, спецификация: `fedresurs.ru/helps/bankrupt/Service_rest_1.0.pdf`. HTTP/JSON, поиск по ИНН/ОГРН/ФИО. Архивы помесячно с 01.2011, новый месяц публикуется не раньше 17 числа | Тоже хороший официальный канал |
| **РНП на zakupki.gov.ru** | Парсинг, плюс есть REST-эндпоинты в EIS — по их публичным выгрузкам можно собирать. Без официального API под широкую публику | Для MVP: парсинг, не критично — РНП обновляется небыстро |
| **ГосЛог** (национальная платформа) | Реестр **экспедиторов** запускается **1 марта 2026** (обязательное уведомление до **1 мая 2026**, см. [[Pinned Facts]] — заявка наша уже подана 9.03.2026). Реестр **перевозчиков** — с **1 марта 2027** (категория N > 3500 кг). Штрафы: ИП 3–10 тыс. ₽, ЮЛ 100 тыс. – 1 млн ₽. Открытого API на 10.05.26 ещё нет — Gemini ничего не знает, в публичных источниках API не упомянут | На MVP — ручная проверка через ЛК Госуслуг. Слежение за анонсом API остаётся в TODO (4-й этап) |

### Платные агрегаторы — актуальные цифры

- **Контур.Фокус**: базовый тариф **32 000 ₽/год** (Россия, экспресс-отчёт, мониторинг 30 контрагентов). Корпоративный с зарубежными — **от 115 000 ₽/год**. Подорожание 15–20% в марте 2025, ещё ~5% в январе 2026. Покрывает: ЕГРЮЛ, ФНС, ФССП, kad.arbitr, ЕФРСБ, госзакупки, аффилированность, финотчётность. Источник: [focus.kontur.ru/site/price](https://focus.kontur.ru/site/price).
- **СПАРК (Интерфакс)**: десятки тысяч ₽ для базового, сотни тысяч ₽ для корпоративных тарифов. Покрытие сопоставимо с Контур.Фокусом.
- **Cargo.ru / ATI**: специализированные на грузоперевозках, цена в районе нескольких тысяч ₽/мес. Для проверки контрагентов годятся как дополнение, не как замена комплексных агрегаторов.

### Что из этого следует для нашего ТЗ

1. **MVP-этап (Этап 1)** реалистично собрать из двух официальных API (ФССП БДИП + ЕФРСБ) плюс парсинга ЕГРЮЛ через сторонний агрегатор `egrul.org` (бесплатно до 100 в день — нам этого с большим запасом). Это закрывает 60–70% риск-сигналов.
2. **Этап 2** — добавляем kad.arbitr через платный сторонний API (одно соглашение, не свой парсер, экономит недели работы). Бюджет: ~1–3 тыс. ₽/мес.
3. **РНП** парсим сами, нагрузка низкая.
4. **ГосЛог** — для экспедиторов уже актуален; интеграции пока нет, на MVP делаем ручную ссылку «открыть ЛК Госуслуг», следим за анонсом API.
5. **Платный агрегатор как fallback**: если на этапе 1 окажется, что времени на собственную сборку нет, **Контур.Фокус** за 32 000 ₽/год покрывает всё, и Carrier Lookup Service деградирует до тонкой обёртки над Фокусом + форма для логиста. Это запасной план B, явно проще и дешевле, чем разработка с нуля. Стоит обсудить.

### Распространённые заблуждения (валидированы)

1. **«Все госданные доступны через простой публичный API»** — неверно. Из 7 источников только 2 (ФССП БДИП и ЕФРСБ) дают официальный REST API. Остальные — либо парсинг, либо сторонние агрегаторы.
2. **«Парсинг госсайтов — это легко и легально»** — спорно. Технически сложно (антиботы, CAPTCHA, AJAX), юридически — серая зона: нарушение пользовательского соглашения и риски, если создаётся высокая нагрузка.
3. **«Бесплатные источники полностью заменят Контур.Фокус»** — нет. Сама ценность платных — это агрегация, нормализация и риск-скоринг. Своими руками это собирается, но это отдельный проект на месяцы. Для нас выбор: вложить эти месяцы или отдать 32 тыс. ₽/год.
4. **«Все данные о перевозчиках в одном госреестре»** — верно «нет», но **с 2026–2027 ГосЛог становится этим реестром де-факто** для экспедиторов и перевозчиков. Через 1–2 года картина существенно упростится.
