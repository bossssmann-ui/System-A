## Что произошло

В репозитории `bossssmann-ui/pacificstar.ru` файл `.env` с боевыми секретами был закоммичен **4 раза**, последний коммит — **14 апреля 2026**: *"Add Telegram bot token and username to .env"*.

Файл добавлен в `.gitignore` **после** коммита. Это не помогает: git-история хранит все версии навсегда.

**Что утекло:**
- `SMTP_PASS` — пароль от почты, через которую идут формы с сайта
- `TELEGRAM_BOT_TOKEN` — токен бота Pacific Star
- `SMTP_USER`, `MAIL_FROM`, `TELEGRAM_BOT_USERNAME` — дополнительные данные

## План закрытия (в порядке приоритета)

### Шаг 1 — Сменить скомпрометированные токены (сделать СЕГОДНЯ)

- [ ] **Telegram Bot Token**: зайти в @BotFather → выбрать бота → `/revoke` → получить новый токен → обновить на сервере/Timeweb
- [ ] **Пароль SMTP**: зайти в почтовый сервис (provider, где `SMTP_HOST`) → сменить пароль → обновить на сервере

> ⚠️ Пока токены не сменены — кто угодно, у кого есть доступ к истории репо, может отправлять письма от имени pacificstar.ru и управлять Telegram-ботом.

### Шаг 2 — Проверить видимость репозитория

- [ ] Зайти на GitHub → репо `bossssmann-ui/pacificstar.ru` → Settings → Danger Zone → проверить: **Public или Private?**
- Если **Public** → срочно перевести в **Private** (это не ломает деплой через GitHub Actions при правильной настройке)
- Если **Private** — риск ниже, но шаг 1 всё равно обязателен (доступ к репо мог быть у других людей)

### Шаг 3 — Очистить git-историю (после смены токенов)

> Это техническая операция. Выполнять после Шагов 1–2.

Два варианта:

**Вариант A (проще): git-filter-repo**
```bash
# Установить: pip install git-filter-repo
git filter-repo --path .env --invert-paths
git push origin --force --all
```

**Вариант B (ядерный): пересоздать репо**
- Создать новый репозиторий
- Скопировать только файлы (без истории)
- Перенастроить GitHub Actions и Timeweb-деплой на новый репо

> После очистки истории — invalidate все старые git clones у всех участников.

### Шаг 4 — Добавить защиту от повторения

- [ ] Установить **git-secrets** или **gitleaks** как pre-commit hook
- [ ] Добавить в `.github/workflows/` job: `gitleaks detect` на каждый push
- [ ] Проверить `.gitignore` — убедиться что `.env` и `.env.*` (кроме `.env.example`) там есть

### Шаг 5 — Закрыть инцидент

- [ ] Обновить статус этого файла: `статус/закрыт`
- [ ] Добавить запись в `30_Decisions/` — что случилось, почему, как закрыли
