# Skill: weekly-inbox-review

> Разбор папки `90_Inbox/` за неделю. Задача — не пропустить важное, не тратить Opus-токены на рутинное чтение.
>
> **Модель-исполнитель:** Haiku (читает и классифицирует) → Sonnet (если нужен синтез или спорные случаи) → Оркестратор проверяет итог.
>
> **Триггер:** каждый понедельник, вручную или по cron. Фраза: "Разбери inbox" / "Что в inbox?" / "Weekly inbox review".

## Входные данные

- Все файлы из `90_Inbox/` (читаем все `.md` и `.txt`)
- Дата последнего разбора (из `90_Inbox/README.md` или `_last_reviewed` метка)
- `99_System/Assistant_Brief.md` — как контекст для классификации

## Алгоритм выполнения

### Шаг 1 — Сбор (Haiku)
Прочитать все файлы в `90_Inbox/`, включая `Quick.md` и дневные заметки (`YYYY-MM-DD.md`). Пропустить `README.md` и файлы в `_AI_staging/`.

### Шаг 2 — Классификация (Haiku)
Каждый элемент inbox отнести к одной из категорий:

| Категория | Признак | Действие |
|---|---|---|
| **TASK** | Есть конкретное действие, срок, ответственный | Вынести в дайджест как задачу |
| **DECISION** | Требует решения собственника | Вынести с вопросом |
| **INFO** | Факт, который надо сохранить | Предложить целевую папку |
| **SOP_CANDIDATE** | Повторяющаяся ситуация | Пометить как кандидат в 20_SOP/ |
| **NOISE** | Мусор без ценности | Предложить удалить |
| **UNCLEAR** | Непонятно без уточнения | Вынести с вопросом к Роману |

### Шаг 3 — Дайджест (Haiku → формат)
Сформировать краткий отчёт в формате:

```
## Inbox Review — [дата]

### Требуют действия (TASK)
- [ ] ...

### Требуют решения (DECISION)
- ? ...

### Предложения по размещению (INFO)
- "..." → переместить в [папка]

### Кандидаты в SOP
- Ситуация "..." повторялась X раз → создать SOP?

### Предложить удалить (NOISE)
- [файл/строка] — причина

### Непонятно — уточнить (UNCLEAR)
- "..." — что имелось в виду?
```

### Шаг 4 — Размещение (только после подтверждения Романа)
Не трогать исходные файлы inbox без явного ОК. Дайджест пишется в `90_Inbox/_AI_staging/inbox_review_YYYY-MM-DD.md`.

### Шаг 5 — Обновление метки
После подтверждения: обновить `_last_reviewed: YYYY-MM-DD` в `90_Inbox/README.md`.

## Правила

1. Никогда не удалять и не перемещать файлы без подтверждения.
2. При классификации сомнительных элементов — UNCLEAR, не угадывать.
3. Если в inbox ничего существенного — сообщить: "Inbox чист, нечего разбирать."
4. Максимум дайджеста — 400 слов. Если больше — что-то пошло не так с объёмом.

