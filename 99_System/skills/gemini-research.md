# Skill: gemini-research

> Исполнитель по умолчанию: **Gemini CLI** (`gemini-2.5-flash`).
> Назначение: research-задача — по теме вернуть факты, источники и follow-up-вопросы. Дешёво, быстро, верифицируется Opus'ом.

## Когда вызывать

- Нужна короткая фактологическая справка по теме (для ТЗ, для решения, для письма).
- Нужно собрать 5–7 ключевых моментов перед тем, как сесть писать длинный документ.
- Нужно прикинуть, что вообще известно о предмете, чтобы понять, куда копать дальше.

**НЕ вызывать, если:**

- Тема содержит чувствительные данные клиента / контрагента (ИНН, тендер) → это Sonnet (см. правила в [[Multi_Agent_Architecture#Правила-маршрутизации-для-меня-самого-v2]]).
- Нужен глубокий аналитический вывод (это writer/critic-цепочка, не research).
- **Нужны актуальные факты после cutoff'а Gemini (2024+) или текущая ситуация на госпорталах** → встроенный `google_web_search` внутри gemini-cli заблокирован из РФ-сети (проверено 10.05.26). В этом случае research делает **Opus через свой WebSearch / WebFetch**, а Gemini вызываем уже как writer/formatter поверх собранных Opus'ом сырых фактов.
- Нужна новость за последние 24 часа → то же самое, делает Opus.

**Что Gemini-research реально умеет в нашей среде:** воспроизвести стабильные знания из своей базы обучения (госпорталы, существующие годами; общие best practices; типовые архитектурные паттерны), оформить их в нашем формате skill'а. Это полезно как стартовый черновик, который Opus потом верифицирует и обогащает свежими фактами.

## Системный промпт (отдаём Gemini)

```
Ты — research-subagent. Получив тему, верни структурированный Markdown:

## Ключевые факты
5–7 пунктов. Каждый пункт — короткий факт + источник в скобках (URL или название).

## Распространённые заблуждения
2–4 пункта. Что обычно путают / неправильно понимают по этой теме.

## Следующие вопросы
3 вопроса, которые имеет смысл задать дальше, чтобы продвинуться по теме.

Без преамбулы и заключения. Кратко, фактично. Если факт спорный — отметить «спорно» и привести оба взгляда.
```

## Шелл-сниппет вызова (для Opus)

```bash
TS=$(date +%Y-%m-%d-%H%M)
SLUG="<короткий-slug-задачи>"   # пример: dispatcher-onboarding-best-practices
TOPIC="<тема одной фразой>"

gemini -m gemini-2.5-flash -p "$(cat /Users/Acer/Documents/System-A/99_System/skills/gemini-research.md | awk '/```$/{f=0} f; /^## Системный промпт/{f=1}' | sed -n '/^```$/,/^```$/p' | sed '1d;$d')

ТЕМА: ${TOPIC}
" > "/Users/Acer/Documents/System-A/99_System/logs/${TS}-research-${SLUG}.md"

cat "/Users/Acer/Documents/System-A/99_System/logs/${TS}-research-${SLUG}.md"
```

> На практике достаточно скопировать блок «Системный промпт» в переменную и подставить тему — это и делает awk выше. Если ломается — проще скопировать промпт руками в `gemini -p "..."`.

### Упрощённый вариант (без awk-магии)

```bash
TS=$(date +%Y-%m-%d-%H%M)
SLUG="dispatcher-onboarding-best-practices"
TOPIC="Best practices онбординга диспетчера в малой логистической компании, 2025"

gemini -m gemini-2.5-flash -p "Ты — research-subagent. По теме верни Markdown с тремя секциями: ## Ключевые факты (5–7 пунктов с источниками), ## Распространённые заблуждения (2–4 пункта), ## Следующие вопросы (3). Без преамбулы.

ТЕМА: ${TOPIC}
" > "/Users/Acer/Documents/System-A/99_System/logs/${TS}-research-${SLUG}.md"
```

## Что Opus делает после вызова

1. Прочитать файл-результат.
2. Беглая верификация: 1–2 факта прогнать через WebSearch / WebFetch на предмет «не выдумано ли». Битые ссылки выкидывать.
3. Дописать в фронтматтер лога: `verdict: ok | needs-rework | failed`.
4. Если результат ОК — синтезировать в нужный артефакт (ТЗ, SOP, заметка в `20_SOP/` или соответствующей зоне).
5. В `99_System/Delegation_Log.md` — одну строку с пометкой «Gemini-research, slug, verdict».

## Формат лога (что Gemini пишет в `99_System/logs/`)

В минимальном варианте — сырой ответ Gemini. Расширенный (когда нужна аналитика):

```markdown
---
date: 2026-05-10T21:09
worker: gemini
model: gemini-2.5-flash
skill: gemini-research
topic: "<тема>"
duration_s: <сек>
verdict: ok
---

<сырой Markdown-ответ Gemini>

## Verification (Opus)
- факт 1: ОК
- факт 2: ссылка битая, выкинуто
```

## Метрика по этому skill

Раз в неделю в self-review считаю:
- Сколько раз вызывался `gemini-research`.
- Какой % `verdict: ok` с первого раза.
- Самые частые причины `needs-rework` (выдуманные источники, поверхностные факты, слишком общая тема — корректирую формулировку темы перед вызовом).

Цель: > 80% «с первого раза» (research проще, чем writing).
