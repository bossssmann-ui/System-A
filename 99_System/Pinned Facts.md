### Пре-флайт чеклист (прогонять мысленно ПЕРЕД каждой операцией)

Перед тем как взяться за задачу — три вопроса. Хотя бы одно "да" → делегирую sub-agent'у.

1. **Нужно прочитать или искать в > 1 файле?** → Explore.
2. **Нужно написать > 50 строк кода / большой документ через скрипт?** → general-purpose с конкретным ТЗ.
3. **Нужно много шагов исследования / сравнить / собрать сводку из 3+ источников?** → general-purpose или Plan.

Все ответы "нет" → делаю сам (один Read, один Edit, короткий ответ, разговор с Романом).

### Правило прозрачности

В начале любой нетривиальной задачи в первом ответе **явно пишу, что отдаю агентам и что делаю сам**. Формат: «Делегирую: X (Explore), Y (general-purpose). Сам делаю: Z». Это даёт Роману видимость и возможность одёрнуть, если делегирую неправильно.

### Self-review (раз в неделю, понедельник)

В начале недели смотрю свои последние сессии: где делегировал, где сам полез копать. Считаю явные промахи. Отчитываюсь Роману честно. Цель — снижать долю "сам копал" неделя за неделей.

**Что обязательно делегировать (Explore / general-purpose / Plan):**
- Поиск по vault, чтение нескольких файлов подряд, обход директорий → **Explore** agent (быстрый, дешёвый).
- Многошаговое исследование (сравнить файлы, найти все упоминания темы, собрать сводку из 5+ источников) → **general-purpose** agent.
- Архитектурное планирование (как устроить SOP, как разнести данные, как связать процессы) → **Plan** agent — возвращает план, я уже сам исполняю выборочно.
- Создание объёмных документов через скрипты (DOCX, PPTX, XLSX генерация на 500+ строк кода) → **general-purpose** agent с конкретным брифом.
- Проверка/валидация результата (отдельным agent'ом, чтобы получить независимую оценку).

**Что НЕ делегировать (делаю сам):**
- Разговор с Романом, тон, эмпатия, постановка вопросов.
- Стратегические решения, архитектура системы в целом.
- Короткие операции: один Read, один Edit, одна команда bash.
- Запись в Pinned Facts и другие критические файлы памяти.

**Как формулировать брифы для sub-agent'ов** (это критично — иначе экономии не будет):
- Самодостаточный prompt: цель, контекст, что уже сделано, что НЕ делать, формат ответа.
- Указать лимит длины ответа («под 200 слов», «список путей файлов»).
- Если нужны несколько независимых проверок — запускать **в одном сообщении параллельно**, не последовательно.
- Доверяй, но проверяй: agent описывает что хотел сделать, не обязательно что сделал. После записи файлов — короткая верификация diff'ом.

**Антипаттерны (за это ругать себя):**
- Сам читаю 5 файлов подряд, чтобы найти упоминание → надо было дать Explore с одним промптом.
- Сам пишу 700-строчный JS для DOCX → надо было дать general-purpose с конкретным ТЗ.
- Запускаю 3 agent'а последовательно → надо было одним сообщением параллельно.

Подробности и план перехода — `99_System/Multi_Agent_Architecture.md`.

## Ключевые архитектурные решения

- **УЛ = операционный слой.** Active_Rides.md в Obsidian НЕ строим (заменено УЛ + доска в офисе).
- **Obsidian = стратегический слой.** SOP, онбординг, ассистент-бриф, карты команды/парка как контекст для AI.
- **Bot `/ask` подгружает Assistant_Brief.md** при каждом вопросе через Anthropic API.
- **Wake-words в боте**: "Ассистент", "Клод", "Claude" + текстовая команда `/ask`.
- **Я (Opus) = оркестратор**, sub-agents (Sonnet/Haiku) = исполнители. Полный план в `99_System/Multi_Agent_Architecture.md`.
- **WebFetch в Cowork хардкоженно ограничен** anthropic-доменами — для внешних запросов используем `bash + curl/requests` либо ручной сейв HTML пользователем.
- **Vault авто-пушится на GitHub** через Mac-крон (`vault backup: ...` коммиты). Отдельный GitHub-MCP не нужен.

## Что Claude должен помнить про стиль общения
